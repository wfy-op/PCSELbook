# Optical Lab project memory

- This directory is an independent npm/Vite/Cloudflare Pages project inside the parent Git repository. Canonical routes: `/` tutorial, `/designer/` workbench. Cloudflare project: `optical-lab-feiyang`; deploy only `dist/`. No book build/data/runtime dependency.
- Tutorial order: computed single-element teaching → calculation/question/build challenges → free optical building → real-photo case. Preserve the eight practical lessons and notes. Group photo confirms only the blue-fiber entrance; other topology and values are teaching assumptions.
- Six pure calculation modules in `app/design/core/` plus `training/{bench-engine,optics,lens-system,learning-model}.ts`. UI, storage and IO stay outside these ten modules. All displayed rays and grading must use real computed results. Do not confuse geometric density with diffraction PSF or claim Zemax equivalence.
- Read `docs/optics-workbench.md` before engine edits. Keep old storage keys and file schemas. Sequential/spatial drafts and libraries stay independent. Cross-domain migration is explicit export, validation, then replacement; never silently discard current designs.
- `npm run dev` owns registered 127.0.0.1:5175 with strictPort. Read global port registry and actual IPv4/IPv6 listeners/process paths before starting/restoring a service. Never stop another project.
- `npm run deploy:pages` must run cleanup/boundary audit, build, unit tests, lint, typecheck and payload audit first. Every optimization release also requires affected `qa:learning`, `qa:workbench`, `qa:usability`. No bare Wrangler bypass. Publication requires user authorization; local build alone is not publication.
- Preserve raw specifications, real-photo inputs and evidence. Recycle disposable files; no permanent-delete fallback. Ignore `outputs/`, `dist/`, `.wrangler/`, `node_modules/`; never deploy them except the verified contents of `dist/`.
- Browser QA uses disposable contexts, existing Playwright via `PCSEL_PLAYWRIGHT_MODULE`, and `PCSEL_OPTICS_URL`. Do not redo passed checks without relevant changes. Screenshots should be batched once and followed by at most one correction/confirmation.
- Stage explicit task files in the parent repository; preserve unrelated book-source and report changes. PCSELbook keeps external links and legacy redirects only. Its migration export component must remain independent of optical engines.
